# v1.0.0 Field Validation

Validation date: 2026-08-26 (Asia/Shanghai)

This report records a real end-to-end exercise of the published v1.0.0 preset,
not a fixture-only or manifest-only test. Codex (model: GPT-5), acting on behalf
of `@philo-x`, followed the installed `speckit.codebase-memory` command as the
coding agent. The command used its documented local CLI fallback because the
MCP tool surface was not exposed in that validation session.

## Procedure

For each repository, the validation performed the following workflow:

1. Established the canonical Git root and recorded the source commit and
   working-tree state.
2. Initialized Spec Kit 1.0.1 where necessary.
3. Installed the exact hosted v1.0.0 tag archive with `specify preset add
   --from ...`.
4. Resolved all six published items: `speckit.codebase-memory`,
   `codebase-context-template`, `speckit.plan`, `speckit.tasks`,
   `speckit.analyze`, and `speckit.implement`.
5. Verified the codebase-memory backend version and current flag contract.
6. Exhausted `list_projects`, then created a deterministic full,
   non-persistent index for the exact canonical root.
7. Required `index_status=ready` with a non-zero graph; read the graph schema;
   requested explicit architecture aspects; searched exact symbols; followed
   relevant result pagination; inspected representative source; traced
   representative call paths with `include_evidence=true`; and ran exact-path
   plus bounded-scope coverage checks.
8. Read build manifests, configuration, CI, deployment/container files,
   documentation, representative production code, and representative tests
   directly.
9. Generated `.specify/memory/codebase.md` from the installed preset-owned
   template and verified the ownership/schema/section contract.
10. Resolved each downstream replacement again with the generated context
    present, confirming that the installed consumer commands remained the top
    layer and referenced `.specify/memory/codebase.md`.
11. Added a unique sentence inside Spring Petclinic's Project Overrides block,
    refreshed a generated frontmatter field, and compared the complete marked
    block before and after the refresh.

Per the command's scope guard, the validation did not run project builds,
tests, containers, applications, package installation, or network-dependent
project commands. It discovered and recorded repository-declared commands
instead.

## CI Enforcement

The repository CI contract is now intentionally fail-closed:

- `requirements-dev.txt` pins `codebase-memory-mcp==0.10.8`.
- GitHub Actions prints package metadata and executes
  `codebase-memory-mcp --version` before pytest.
- `test_installed_codebase_memory_backend_contract` has no `skipif`; it fails
  with a clear assertion if the executable is absent.
- The test enforces version >=0.10.8 and checks the required pagination,
  indexing, evidence, and coverage flags on the installed executable.

Thus a green workflow can no longer mean “preset structure passed while the
backend contract was silently skipped.”

## Limitations

- `check_index_coverage` is a best-effort recorded-gap signal, not proof of
  parser or semantic completeness.
- Generated outputs are static engineering context. They do not prove runtime
  traffic, active profiles, transaction success, external availability, or
  production security posture.
- The validation exercised the local CLI fallback. MCP and CLI share the
  backend implementation, but transport-level MCP invocation was not separately
  field-tested in this session.
- Project build/test commands were intentionally not executed by the generator;
  CI enforcement here validates the preset and backend contract, not the two
  target repositories' application behavior.

## Outcome

The v1.0.0 preset completed the intended install -> resolve -> index -> verify
-> generate -> refresh -> downstream-resolution path on both a generic Python
codebase and a Spring Boot Maven codebase. The observed graph gaps were surfaced
as limitations and supplemented with direct evidence. CI now makes the external
backend contract mandatory rather than optional.
