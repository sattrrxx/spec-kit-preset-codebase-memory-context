# v1.0.1 MCP and Workflow Validation

Date: 2026-08-26

This follow-up closes two gaps left explicit in the
[v1.0.0 field-validation report](v1.0.0.md): it exercises the real MCP stdio
transport, and it runs the generated context through the complete downstream
`plan -> tasks -> analyze -> implement` lifecycle in a disposable Git project.

## Subject Under Test

- Preset: `codebase-memory-context` v1.0.1
- Spec Kit: development checkout supporting preset manifests v1.0
- Backend: `codebase-memory-mcp==0.10.8`
- Platform: macOS arm64, Python 3.13
- Automated preset suite: 14 tests

The release archive and hosted CI results are recorded in the release notes and
linked from this report after publication. The immutable v1.0.0 evidence
remains in its original report.

## MCP Stdio Validation

The backend was started as a stdio MCP server. A client sent, in order:

1. JSON-RPC `initialize` with protocol version `2025-06-18`;
2. `notifications/initialized`;
3. `tools/list`; and
4. `tools/call` for the read-only `list_projects` tool with `limit=1` and
   `offset=0`.

Observed results:

- server name `codebase-memory-mcp`, version `0.10.8`;
- negotiated protocol version `2025-06-18`;
- the required generator surface was present, including `index_repository`,
  `search_graph`, `trace_path`, `get_code_snippet`, `get_architecture`,
  `list_projects`, `index_status`, and `check_index_coverage`; and
- `tools/call` returned `isError: false` with structured project-list content.

`tests/test_preset.py::test_installed_codebase_memory_mcp_stdio_contract`
repeats this entire exchange in CI. It has no skip path and a 30-second timeout.
This complements the existing executable-version and CLI-flag contract test.

## Downstream Workflow Smoke Test

### Fixture and installation

A new disposable Git repository was created at root commit
`4a081d6cf023bed4c61bac1d98e6af9c937336f7`. It contained a typed `greeting`
function in `app.py`, one pytest test in `test_app.py`, and a README-declared
test command. Spec Kit initialized the repository with the Codex integration,
Python scripts, and the local v1.0.1 preset. `specify preset list` reported the
preset enabled with six templates, and every generator/consumer resolve command
reported `codebase-memory-context v1.0.1` as its top layer.

### Context generation evidence

`codebase-memory-mcp` performed a fresh full, nonpersistent index:

- project: `private-tmp-spec-kit-v101-smoke.MsdD1w`;
- 754 nodes and 1,182 edges;
- graph search resolved `greeting` and its test;
- architecture reported the `test_app -> app` boundary and their CALLS edge;
- exact coverage checks for `app.py`, `test_app.py`, and `README.md` returned
  matching metadata with no recorded issue; and
- root-scope gaps were confined to generated Bash helper parse ranges and
  excluded tool/cache directories.

The generated `.specify/memory/codebase.md` recorded these findings, qualified
negative claims to the bounded application scope, and retained the Project
Overrides markers. Coverage remains best-effort and is not presented as proof
of completeness.

### Context consumption by each workflow

The feature requested a reusable whitespace-normalizing function while
preserving the existing greeting behavior.

| Stage | Observable context consumption |
|---|---|
| Plan | Chose the existing flat `app.py` / `test_app.py` layout, type annotations, docstrings, exact pytest assertions, and the repository-declared test command. No external research was needed. |
| Tasks | Targeted the two verified files and omitted generic setup, packaging, database, API, security, and integration tasks that the context did not support. |
| Analyze | Corroborated every context-derived path and command against current source, checked requirement-to-task traceability, disclosed graph coverage gaps, and made no repository-alignment claim above its allowed evidence. |
| Implement | Added the test first, observed the expected import failure, implemented only the planned function, preserved `greeting`, and ran the declared test command. |

The final implementation result was `2 passed in 0.00s`, including the original
greeting assertion and all new normalization assertions. All tasks were marked
complete only after that run.

## Automated Enforcement

The test suite now enforces all of the following:

- pinned backend installation and minimum version;
- required CLI flags;
- real MCP initialization, tool discovery, and a read-only tool call;
- manifest and replacement-layer resolution;
- generator/template contract and Project Overrides markers; and
- Codex, Copilot, and Gemini rendered install/remove flows.

Local result before publication: `14 passed`.

## Limitations

- The smoke fixture is intentionally minimal; the v1.0.0 report remains the
  stronger evidence for large generic and Spring Boot Maven repositories.
- The workflow was agent-driven against installed command instructions rather
  than a deterministic shell implementation of natural-language commands.
- Stdio MCP transport was verified; other transports are outside this preset's
  declared compatibility contract.
- Static graph evidence does not prove production runtime behavior.
